## Scope of this preview

`v0.1.0-preview` is the first publicly-discoverable Cephalon Engine snapshot. It targets `net10.0` (LTS) with `net11.0` readiness in progress (Preview 3 verified; Preview 4 expected on or near `May 12, 2026`). The preview ships:

- **103 `Cephalon.*` packages** plus the new `Cephalon.Resilience` extracted in Sprint 125 (104 total)
- **public API contract lock-in** across every shipped package via `Microsoft.CodeAnalysis.PublicApiAnalyzers` + `PublicAPI.Shipped.txt` / `PublicAPI.Unshipped.txt` artefacts
- **engine-boundary redaction surface** (`IRedactionFilter` + `RedactionContext` + `RedactionPipeline`) wired at seven real M1 emission sites: `Cephalon.AspNetCore` HTTP middleware, `Cephalon.Engine` runtime module-phase tags, `Cephalon.Eventing.Wolverine` dispatch tags, `Cephalon.Agentics` tool-dispatch tags (`agentics.tool.dispatch`), `Cephalon.Retrieval` knowledge-indexing + knowledge-query tags (`retrieval.knowledge.index` + `retrieval.knowledge.query`), `Cephalon.Worker` lifecycle-start + lifecycle-stop tags (`worker.lifecycle.start` + `worker.lifecycle.stop` with `cephalon.lifecycle.phase` / `cephalon.blueprint` / `cephalon.module.count`), and `Cephalon.Eventing` in-process publication-dispatch tags (`eventing.publication.dispatch` span emitted under `CephalonActivitySources.Eventing` with publisher / publication / channel / event-type / outcome / matched-subscription-count identifiers)
- **39+ redaction-suite tests** covering the contract types, starter filters, orchestration, DI extension, and three core M1 emission-site integrations (AspNetCore middleware + EngineRuntime + Wolverine dispatch); the Agentics and Retrieval emission sites adopt the same `Redact(activity, key, value)` helper pattern verified in those integration tests
- **central diagnostic-id registry** (`docs/diagnostic-id-registry.md`) cataloguing every allocated `EventId` range across 14 packages with reserved-gap discipline
- **complete documentation refresh** across 11 reference docs (`engine-backlog`, `components/diagnostics`, `engine-surface-maturity-audit`, `operational-hardening-gap-inventory`, `getting-started`, `architecture-review-2026-04` + `-05`, `conformance-matrix`, `engine-roadmap`, `runtime-contract-index`) plus per-page maturity-badge frontmatter on all 104 component docs

This is a **preview release**, not GA. Public API binary stability is not yet promised — see *Compatibility posture* below.

## What's new in this preview

### Engine-boundary redaction (`ENG-357..380`, `ENG-390`, `ENG-371`, `ENG-401`, `ENG-402`, `ENG-409`, `ENG-412`, `ENG-413`, `ENG-415`, `ENG-417`..`ENG-424`)

Consumer apps now register synchronous `IRedactionFilter` implementations (one or more) plus call `IServiceCollection.AddRedactionPipeline()` once. The engine pipes attribute values through the registered pipeline at **seven** real emission sites before exporter dispatch:

- `Cephalon.AspNetCore`'s HTTP request/response logging middleware (HTTP request/response span tags + activity events)
- `Cephalon.Engine`'s module-phase runtime activity tags (`runtime.{phase}` + `module.{phase}` spans during initialize/start/stop)
- `Cephalon.Eventing.Wolverine`'s dispatch-time activity tags (`wolverine.dispatch` spans including `cephalon.tenant_id` / `cephalon.correlation_id` / `cephalon.message_id`)
- `Cephalon.Agentics`'s in-process tool-dispatch activity tags (`agentics.tool.dispatch` span emitted under `CephalonActivitySources.Agentics` with dispatcher / tool / run / actor / correlation identifiers)
- `Cephalon.Retrieval`'s knowledge-indexing and knowledge-query activity tags (`retrieval.knowledge.index` and `retrieval.knowledge.query` spans emitted under `CephalonActivitySources.Retrieval` — `KnowledgeIndexer` and `KnowledgeQueryEngine` both consume the redaction pipeline before tagging activities)
- `Cephalon.Worker`'s lifecycle activity tags (`worker.lifecycle.start` and `worker.lifecycle.stop` spans emitted under `CephalonActivitySources.Worker` with `cephalon.lifecycle.phase` / `cephalon.blueprint` / `cephalon.module.count` tags — `RuntimeHostedService` lazily resolves the redaction pipeline from `IServiceProvider` and wraps every `SetTag` through the same `Redact(activity, key, value)` helper pattern used at the other five sites)
- `Cephalon.Eventing`'s in-process publication-dispatch activity tags (`eventing.publication.dispatch` span emitted under `CephalonActivitySources.Eventing` with publisher / publication / channel / event-type / outcome / matched-subscription-count identifiers; `InProcessEventPublisher` resolves the redaction pipeline lazily from DI per the same helper pattern used at the other six sites — shipped through `ENG-371`)

Starter filter implementations ship under `Cephalon.Diagnostics.Redaction.Defaults`:

- `KeyMatchRedactionFilter` — redacts values whose `RedactionContext.AttributeKey` matches a banned set (ordinal-case-insensitive); replacement defaults to `"[REDACTED]"`
- `RegexRedactionFilter` — replaces regex-matched substrings inside string values; non-string values pass through unchanged

The orchestration helper `RedactionPipeline` composes filters in DI registration order, where each filter sees the previous filter's output. Consumer apps can register any number of filters or compose pipelines hierarchically — see [`docs/components/diagnostics.md`](../components/diagnostics.md#redaction-quick-start) for the canonical adoption recipe and [`samples/Cephalon.Sample.ModularMonolith`](../../samples/Cephalon.Sample.ModularMonolith/ModularMonolithSampleApp.cs) for a runnable example.

The build-time `engine.build` activity (3 tags emitted before DI is wired) is **deliberately out of scope** for redaction — the values are internally-derived from the manifest and non-sensitive by construction; consumers needing redaction here should rename the blueprint instead.

**Engine-quality dimensions advanced**: Security, Auditability, Compliance, Reliability.

### Diagnostic-id registry (`ENG-370`)

Every `EventId` allocation across 14 `Cephalon.*` packages is now catalogued in [`docs/diagnostic-id-registry.md`](../diagnostic-id-registry.md), the authoritative central allocation table. The convention block declares one range per package, contiguous ascending allocation, default 10-event range, `EventId.Name = nameof(field)`, and a no-new-allocations-below-2000 collision guard.

**Engine-quality dimensions advanced**: Maintainability, Auditability.

### `Cephalon.Resilience` extraction (`ENG-390`)

The engine-resilience runtime (Polly v8 + `Microsoft.Extensions.Resilience` policy resolver, circuit-breaker state registry, exception classifier, execution-context keys) is now its own package separate from `Cephalon.Behaviors`. Consumers can adopt the resilience surface without taking the full behavior dispatch runtime.

The four runtime types (`BehaviorResiliencePolicyResolver`, `BehaviorCircuitBreakerStateRegistry`, `DefaultBehaviorResilienceExceptionClassifier`, `BehaviorResilienceExecutionContextKeys`) moved with git-tracked rename history preserved at 92-99% similarity. The remaining three types (`BehaviorResilienceExecutionMiddleware`, `BehaviorIdempotencyResolver`, `BehaviorResilienceRuntimeCatalog`) stayed in `Cephalon.Behaviors` because moving them would have required widening currently-internal surface or created circular project references.

**Engine-quality dimensions advanced**: Reliability, Compatibility, Maintainability.

### Public API contract lock-in across 100+ packages (`ENG-322..345`)

Every shipped `Cephalon.*` package now carries `Microsoft.CodeAnalysis.PublicApiAnalyzers` plus `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt` artefacts. The analyzer enforces:

- `RS0016` — undeclared API additions fail the build
- `RS0017` — declared API removals require explicit `*REMOVED*` entries
- `RS0026`/`RS0027` — optional-overload-style discipline (no longer suppressed across the codebase as of `ENG-371`)

**Engine-quality dimensions advanced**: Compatibility, Maintainability.

### `Cephalon.Diagnostics` `M2`→`M3`→`M4` promotion (`ENG-351`, `ENG-354`)

The canonical activity-source / meter / attribute-key surface graduated from `M2` through `M4` over Sprint 125:

- `M2` — host adapters consume canonical names (`Cephalon.AspNetCore` + `Cephalon.Worker`)
- `M3` — operator surface lands (`/engine/diagnostics-conventions` projecting `DiagnosticsConventionsSurface`)
- `M4` — `Cephalon.Observability.OpenTelemetry` subscribes to all canonical sources / meters as the OTLP companion pack's real subscription contract

`Cephalon.Eventing` and `Cephalon.MultiTenancy.Governance` canonical names extended in `ENG-355`; `Cephalon.Agentics` and `Cephalon.Retrieval` pre-declared in `ENG-381`.

**Engine-quality dimensions advanced**: Auditability, Compatibility.

### Sample adoption (`ENG-368`/`ENG-369`)

The redaction recipe (`KeyMatchRedactionFilter` for sensitive headers + `RegexRedactionFilter` for credit-card patterns + `RegexRedactionFilter` for Bearer tokens with prefix-preserving replacement) is wired into all 5 samples: `Cephalon.Sample.ModularMonolith`, `Cephalon.Sample.Microservice`, `Cephalon.Sample.ModularVerticalSlice`, `Cephalon.Sample.MicroserviceSuite` (Catalog + Orders services), `Cephalon.Sample.Showcase`. Consumer apps can copy the recipe from any sample.

### Per-page maturity-badge convention (`ENG-382..387`, `ENG-393`)

All 104 component docs under `docs/components/` now carry an inline frontmatter blockquote with the package's maturity (`M0`-`M4`) + ownership (`taxonomy-only` / `application-managed` / `cephalon-managed` / `provider-managed` / `mixed`) right under the H1, plus a pointer to the authoritative maturity audit. Adopters reading any page see the maturity label without scrolling.

### Stale `<NoWarn>` suppression cleanup (`ENG-371..373`)

The `RS0026`/`RS0027` `<NoWarn>` suppressions added during the contract-lock-in arc were stripped from 100 csproj files (verified empirically: lifting the suppression produces 0 violations). Surviving suppressions on `Cephalon.AspNetCore.Grpc` (`RS0041` for `Grpc.Tools`-generated nullable-oblivious code) and the test projects (`CA1707` for xUnit underscore-naming) carry inline rationale comments.

**Engine-quality dimensions advanced**: Maintainability.

## Compatibility posture

`v0.1.0-preview` is **not** binary-stable yet. Per [`docs/compatibility.md`](../compatibility.md), `<EnablePackageValidation>true</EnablePackageValidation>` and `<PackageValidationBaselineVersion>` flip on when the engine cuts its **first GA release post-`0.1.0-preview`**. Until then:

- public API additions land directly in `PublicAPI.Unshipped.txt` and graduate to `PublicAPI.Shipped.txt` at each release tag
- public API removals are tolerated but should follow the `[Obsolete]` discipline declared in `compatibility.md` when the slice can afford it
- binary-breaking refactors are acceptable but should be flagged in this release-notes draft for the next preview cycle
- consumers taking a binary dependency on Cephalon during the preview window should pin exact versions and re-baseline at each preview release

The first stable GA release will adopt `<EnablePackageValidation>true</EnablePackageValidation>`, `<PackageValidationBaselineVersion>0.1.0</PackageValidationBaselineVersion>`, and SemVer 2.0 + .NET binary compatibility rules per the [engineering standards](../engineering-standards.md) baseline.

## Supply-chain posture

`v0.1.0-preview` ships through the SLSA L3 + Sigstore + CycloneDX SBOM pipeline declared in [`docs/supply-chain-uplift-plan.md`](../supply-chain-uplift-plan.md). The first tag-triggered run will produce:

- SLSA Level 3 provenance (GitHub Actions OIDC + signed attestation)
- Sigstore Cosign signature on every `.nupkg` (Fulcio cert + Rekor transparency log entry)
- CycloneDX SBOM bundle covering every transitive dependency
- NuGet vulnerability audit report from the default release-validation gate
- NuGet trusted-publishing token (no static API key)

The release-pipeline workflow lives at `.github/workflows/publish-release.yml` and runs on `v*.*.*` tags only.

## Known gaps and limitations

**Open at this preview** (per `architecture-review-2026-05.md` *Updated risks* / *Updated gaps*):

- **Maturity-label asymmetry**: human-facing component docs now carry the badge, but `getting-started.md` flow and template-pack starter projects don't yet surface maturity prominently in the path-to-adoption (Risk #2)
- **Trim / AOT / single-file claim story**: `scripts/deployment-mode-support.json` and `cephalon doctor` still declare `not-claimed` posture; the validation harness that lets future claims become real support statements is open (Risk #3, Gap #3)
- **Default-path dilution risk**: low-ceremony shorthand around REST `RestApi:AuthoringPolicies`, generated profile groups, and host-governance scope refinements stays truthful for now but should be re-checked each quarter (Risk #4)
- **Sub-agent and AI-tooling reversibility**: `project-memory.md` pins specific tooling decisions (Codex CLI 5.5, `Cephalon-Neza` git account); these must stay reversible as AI tooling evolves through 2026-2027 (Risk #5)

## How to consume this preview

```pwsh
# Restore Cephalon.* packages with locked-mode discipline
dotnet restore --locked-mode CephalonEngine.slnx

# Build against .NET 10 LTS
dotnet build CephalonEngine.slnx -c Release

# Run the redaction integration tests as a smoke check
dotnet test --filter "FullyQualifiedName~Cephalon.Tests.Diagnostics.Redaction"
```

Adopt the canonical redaction recipe in any consumer-app composition root. The full recipe is in [`docs/components/diagnostics.md`](../components/diagnostics.md#redaction-quick-start).
