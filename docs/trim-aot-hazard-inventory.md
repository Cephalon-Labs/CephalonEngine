# Trim / Native AOT / Single-file hazard inventory

> See also: [`deployment-mode-support.md`](deployment-mode-support.md), [`compatibility.md`](compatibility.md), [`engineering-standards.md`](engineering-standards.md), [`dotnet11-readiness.md`](dotnet11-readiness.md), [`engine-roadmap.md`](engine-roadmap.md), [`architecture-review-2026-05.md`](architecture-review-2026-05.md), [`conformance-matrix.md`](conformance-matrix.md)

This document records the **actual reflection / dynamic-code patterns observed in shipped `src/Cephalon.*` runtime code as of May 6, 2026**, classified by their impact on a future trim / Native AOT / single-file claim. It is the concrete inventory feeding the validation-harness work declared in [`deployment-mode-support.md`](deployment-mode-support.md) (`representativePublishTargets`, per-package `deploymentModeEligibility`, and `knownTransitiveHazards` manifest fields).

It does **not** widen the global support contract. Trim, Native AOT, and single-file remain globally `not-claimed` until the manifest, harness, project properties, docs, and release-validation flow promote those rows together. Package-scoped `supportedModes` claims can move earlier only when the specific package is listed in `scripts/deployment-mode-support.json`, carries matching project properties, and passes the harness's package-claim audit path.

## Scope and method

- **Sources searched.** Every `src/Cephalon.*/*.cs` file under the repo, plus every `src/Cephalon.*/*.csproj` for explicit trim / AOT property declarations.
- **Patterns flagged (extended via `ENG-433`).** The `ENG-426` first-pass query covered `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, and `Assembly.LoadFrom`. The `ENG-432` deeper read of `Cephalon.Behaviors.Http` revealed that real hazards routinely show up under `MakeGenericMethod`, `MethodInfo.Invoke`, and `BindingFlags.NonPublic`-style member lookups — patterns the first-pass query did not match. The current pattern set is therefore: `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, `MakeGenericMethod`, `Assembly.LoadFrom`, `MethodInfo.Invoke`, `BindingFlags.\*`, `\.InvokeMember\(`, `Expression.Lambda`, `TypeBuilder` / `DynamicMethod` / `ILGenerator` / `Emit\.\*`, plus `[DynamicallyAccessedMembers]`, `[RequiresUnreferencedCode]`, and `[RequiresDynamicCode]` annotations.
- **Method.** Pattern matches were classified by the actual call site, not by attribute presence. As of May 6, 2026, **no Cephalon runtime type carries `[RequiresUnreferencedCode]` / `[RequiresDynamicCode]` annotations** — every entry below is a pre-annotation hazard. The validation harness will gate annotation rollout on the matching project properties (`PublishTrimmed`, `PublishAot`, etc.) being intentionally set.
- **Known not-yet-classified hazard surface (`ENG-433` first-pass under broadened patterns).** The broadened `Grep` (May 5, 2026) surfaced additional `MakeGenericMethod` / `BindingFlags`-based hazards in `Cephalon.Behaviors` (`Modules/BehaviorModule.cs` lines 347/356/388/494; `Services/BehaviorExecutionSlot.cs` lines 73-74), `Cephalon.Behaviors.Http` beyond the four sites already classified by `ENG-432` (`Hosting/RestBehaviorProjection.cs` lines 43/207, `Hosting/RestBehaviorModuleBuilder.cs` line 230, `Hosting/BehaviorRestProfileResolver.cs` lines 155/192), and `Cephalon.ReferenceDocs` (`Generation/ReferenceDocsGenerator.cs` lines 295/301/308/313 enumerate constructors/fields/properties/methods on arbitrary types — by design for doc generation but trim-hostile). These are flagged here so a future audit slice can classify them; they are **not** yet recorded in the per-tier tables below to avoid landing classifications without a deeper read of each call site (the `ENG-432` precedent showed first-pass classifications materially understate hazards). The CDC capture services in `Cephalon.Data.MySql` / `Cephalon.Data.Postgres` / `Cephalon.Data.Oracle` were on this list and were classified through `ENG-434`'s deeper read; the MySQL hosted-service duck-typed failure metadata entries were later retired by `ENG-459`, and the matching Postgres / Oracle entries were retired by `ENG-460`. The `Cephalon.Abstractions` enum-field lookups (across `RestEndpointAuthoringPolicySuppressionKind`, `RestEndpointBindingFallbackMode`, `RestEndpointBindingSource`, `RestEndpointCandidateStatus`, `RestEndpointGovernanceRuleSelectionBasis`, `RestEndpointOverrideActionKind`, `RestEndpointOverrideBindingMode`) plus the matching `Cephalon.Behaviors.Http.Abstractions.BehaviorRestMethod` / `BehaviorRestBindingSource` extensions were also on this list, were classified through `ENG-435`'s deeper read, and have now been retired by `ENG-456` through closed switch mappings (see the retired low-tier note below). The `Cephalon.Behaviors` items (`Modules/BehaviorModule.cs` lines 350/359/384/416/455/521; `Services/BehaviorExecutionSlot.cs` lines 73-74) were also on this list, were classified through `ENG-436`'s deeper read as additional `high`-tier evidence inside the existing `Cephalon.Behaviors` package row, and were updated by `ENG-457` when the source generator added `GetExecutionSlots()` hints plus a matching carrier-method lookup (see the new sub-section below). The `Cephalon.Behaviors.Http` items (`Hosting/RestBehaviorProjection.cs` lines 43/207, `Hosting/RestBehaviorModuleBuilder.cs` lines 14/19/230, `Hosting/BehaviorRestProfileResolver.cs` lines 153/190) were also on this list and have now been classified through `ENG-437`'s deeper read as additional `medium`-tier evidence inside the existing `Cephalon.Behaviors.Http` package row (see the new sub-section below); the package's overall tier remains `medium` because the dominant blocker is still the open-generic *method* dispatch in `BehaviorRestEndpointGroup.cs:486` per `ENG-432`. The `Cephalon.ReferenceDocs` items (`Generation/ReferenceDocsGenerator.cs` lines 295/301/308/313) were also on this list and have now been classified through `ENG-438`'s deeper read as a new `high`-tier package entry with a permanent `not-claimed` posture (see the new sub-section below); the reflection here is by-design type-introspection of arbitrary types passed in via assembly references — the package is the documentation generator that enumerates other Cephalon.* runtime packages — so the `high`-tier remediation alternative already named in the [severity classification](#severity-classification) (a permanent `not-claimed` posture for that package) is the durable answer. After this slice every item in the original `ENG-433` not-yet-classified callout has been closed.
- **Out of scope.** Test, benchmark, sample, and tooling projects. Concrete provider packs only appear when their `Cephalon.*` runtime surface itself contains a hazard pattern (transitive provider-SDK hazards belong in the harness's `knownTransitiveHazards` list, not here).

## Severity classification

| Severity | Meaning | Required remediation before a `claimed` deployment-mode posture |
| --- | --- | --- |
| `excluded-by-design` | Roslyn analyzer / source-generator project that runs in the compiler, never in published output. Properties already declare `IsTrimmable=false`, `IsAotCompatible=false`, `PublishTrimmed=false`, `PublishAot=false`, `PublishSingleFile=false`. | None — the project is intentionally outside the deployment-mode story. |
| `clean-baseline` | Runtime package with no observed reflection / dynamic-code patterns in its `Cephalon.*` source. | Confirm transitive dependencies are clean against the harness's analyzer phase before adopting any `claimed` mode. |
| `low` | Reflection is bounded to closed-generic instantiation over a small known set of types and is reachable only through engine-internal seams. Likely fixable with `[DynamicallyAccessedMembers]` annotations or a small generic-shape rewrite. | Annotate or rewrite, then re-validate. |
| `medium` | Reflection over types loaded from data (e.g. `Type.GetType(persistedString)`). The provider can lift this to AOT-safe by registering a serializer table or polymorphic JSON converter, but the change is non-trivial and the manifest must declare the provider as `claim-overstated` until done. | Replace with a compile-time type registry or polymorphic `System.Text.Json` `[JsonPolymorphic]` baseline. |
| `high` | Reflection that depends on assembly scanning, runtime-loaded plugins, or open-generic adapter instantiation. Cannot become AOT-safe without a structural rewrite (typically a source generator or compile-time discovery contract). | Replace with a source generator + compile-time descriptor, or document a permanent `not-claimed` posture for that package. |

A package is only as portable as its highest hazard. A `Cephalon.EventSourcing.*` provider that uses `Type.GetType` is `medium` even if the rest of its surface is clean.

### `high` — additional `Cephalon.Behaviors` evidence: module-discovery pipeline + execution-slot dispatch (added via `ENG-436`, updated via `ENG-457`)

`Cephalon.Behaviors` already sits in the `high` tier because its `BehaviorTypeRegistry` resolves behavior types from runtime descriptors. The deeper read enumerated by `ENG-433` and now classified here surfaces the actual reflection sites that *populate* that registry plus the open-generic *method* dispatch that *consumes* it. Two files together make up this evidence:

- **`Modules/BehaviorModule.cs`** runs a two-phase auto-registration pipeline (line 305 `AutoRegisterBehaviors`). **Phase 1** (lines 335-422, `TrySourceGeneratedRegistration`) reads `assembly.GetCustomAttribute<ContainsBehaviorsAttribute>()` to find a source-generator-emitted registration class, then reflectively looks up and invokes its `Register` / `GetExecutionSlots` / `GetTopologyDescriptors` / `GetBehaviorsNeedingRuntimeTopology` methods by name; in isolation this is annotation-recoverable through `[DynamicallyAccessedMembers]` on the attribute's `RegistrationType` property. **Phase 2** (lines 446-495, `ReflectionScanAssembly`) is a canonical assembly-scan: `assembly.DefinedTypes` enumeration plus interface-shape checks plus `AppBehaviorAttribute` lookup. Both paths converge on `BuildTopologyDescriptorFromStaticMethod` (line 517) which reflectively looks up a static `ConfigureTopology` method on each behavior type. Because the phase-2 fallback exists, the package's overall blocker remains assembly scanning; remediation is the same source-gen-emitted compile-time module manifest + behavior-registration table that retires `BehaviorTypeRegistry` itself.
- **`Services/BehaviorExecutionSlot.cs`** still carries a fallback that materializes a per-behavior execution slot through open-generic *method* dispatch over the runtime `(behaviorType, TInput, TOutput)` triple discovered from the registry. `ENG-457` moved the normal source-generated path to generated closed-generic `BehaviorExecutionSlot.For<TBehavior, TInput, TOutput>()` slot hints, so this fallback is now narrower, but it remains a real deployment-mode hazard for assemblies without generated hints or behaviors discovered through runtime scanning.

The package's overall tier remains `high` (unchanged); these entries are recorded here so the harness sees the full reflection surface of the package, not just the registry-entry seam. Manifest seeding has been extended in lockstep so `scripts/deployment-mode-support.json` `deploymentModeEligibility.packages[Cephalon.Behaviors].knownHazards` lists every site below.

### `high` — non-public reflective access on a third-party transport type in `Cephalon.Data.MySql` (added via `ENG-434`)

### `high` — by-design type-introspection in `Cephalon.ReferenceDocs` (added via `ENG-438`)

`Cephalon.ReferenceDocs` is the published documentation generator (an `OutputType=Exe` package shipped through the same release-validation flow as the other `Cephalon.*` runtime packages, listed alongside them in `scripts/validate-signed-package-governance.ps1`). Its job is to enumerate the public API surface of arbitrary other `Cephalon.*` runtime packages — that is what produces `docs/reference/*.md`. The reflection in `Generation/ReferenceDocsGenerator.cs` therefore enumerates constructors, fields, properties, and methods on **types loaded from external assembly references**, by design.

Because the input types are not known at compile time and are not bounded to any closed set (the generator is supposed to document any public type from any reference Cephalon package), there is no source-generator or compile-time descriptor that retires this reflection — the by-design contract of the package is exactly the reflection it performs. Per the [severity classification](#severity-classification), the `high` tier offers two remediation paths: "Replace with a source generator + compile-time descriptor, or document a permanent `not-claimed` posture for that package." The first path is incompatible with the package's purpose; the second path is the durable answer for `Cephalon.ReferenceDocs`. The package therefore stays `not-claimed` for trim / Native AOT / single-file *as a deliberate engineering decision*, not as an unresolved hazard. The matching csproj posture properties (`IsTrimmable=false; IsAotCompatible=false; PublishTrimmed=false; PublishAot=false; PublishSingleFile=false`) were declared in `src/Cephalon.ReferenceDocs/Cephalon.ReferenceDocs.csproj` via `ENG-439` and seeded into the matching `requiredProjectProperties` array in `scripts/deployment-mode-support.json`'s `Cephalon.ReferenceDocs` package entry, so the harness's project-property audit phase can confirm the permanent posture in machine-checkable form.

- introduces a new `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, or `Assembly.LoadFrom` call site in any `src/Cephalon.*` package, **or**
- removes / annotates one of the call sites listed above, **or**

- adds, removes, or changes a package-scoped `supportedModes` claim or its required project properties, **or**
- ships a structural remediation (source-generator, compile-time registry) that retires one of the entries here.

A no-change month (no slice touched any of those surfaces) does not require an update; the doc records the state-as-of date in its first-paragraph review window.
