# Trim / Native AOT / Single-file hazard inventory

> See also: [`deployment-mode-support.md`](deployment-mode-support.md), [`compatibility.md`](compatibility.md), [`engineering-standards.md`](engineering-standards.md), [`dotnet11-readiness.md`](dotnet11-readiness.md), [`engine-roadmap.md`](engine-roadmap.md), [`architecture-review-2026-05.md`](architecture-review-2026-05.md), [`conformance-matrix.md`](conformance-matrix.md)

This document records the **actual reflection / dynamic-code patterns observed in shipped `src/Cephalon.*` runtime code as of May 6, 2026**, classified by their impact on a future trim / Native AOT / single-file claim. It is the concrete inventory feeding the validation-harness work declared in [`deployment-mode-support.md`](deployment-mode-support.md) (`representativePublishTargets`, per-package `deploymentModeEligibility`, and `knownTransitiveHazards` manifest fields).

It does **not** widen the global support contract. Trim, Native AOT, and single-file remain globally `not-claimed` until the manifest, harness, project properties, docs, and release-validation flow promote those rows together. Package-scoped `supportedModes` claims can move earlier only when the specific package is listed in `scripts/deployment-mode-support.json`, carries matching project properties, and passes the harness's package-claim audit path.

## Scope and method

- **Sources searched.** Every `src/Cephalon.*/*.cs` file under the repo, plus every `src/Cephalon.*/*.csproj` for explicit trim / AOT property declarations.
- **Patterns flagged (extended via `ENG-433`).** The `ENG-426` first-pass query covered `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, and `Assembly.LoadFrom`. The `ENG-432` deeper read of `Cephalon.Behaviors.Http` revealed that real hazards routinely show up under `MakeGenericMethod`, `MethodInfo.Invoke`, and `BindingFlags.NonPublic`-style member lookups — patterns the first-pass query did not match. The current pattern set is therefore: `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, `MakeGenericMethod`, `Assembly.LoadFrom`, `MethodInfo.Invoke`, `BindingFlags.\*`, `\.InvokeMember\(`, `Expression.Lambda`, `TypeBuilder` / `DynamicMethod` / `ILGenerator` / `Emit\.\*`, plus `[DynamicallyAccessedMembers]`, `[RequiresUnreferencedCode]`, and `[RequiresDynamicCode]` annotations.
- **Method.** Pattern matches were classified by the actual call site, not by attribute presence. As of May 6, 2026, **no Cephalon runtime type carries `[RequiresUnreferencedCode]` / `[RequiresDynamicCode]` annotations** — every entry below is a pre-annotation hazard. The validation harness will gate annotation rollout on the matching project properties (`PublishTrimmed`, `PublishAot`, etc.) being intentionally set.
- **Known not-yet-classified hazard surface (`ENG-433` first-pass under broadened patterns).** The broadened `Grep` (May 5, 2026) surfaced additional `MakeGenericMethod` / `BindingFlags`-based hazards in `Cephalon.Behaviors`, `Cephalon.Behaviors.Http`, and `Cephalon.ReferenceDocs`; those first-pass findings are now all classified, retired, or intentionally documented. CDC capture failure metadata reflection was classified through `ENG-434` and retired through `ENG-459` / `ENG-460`; REST wire-name enum-field reflection was classified through `ENG-435` and retired by `ENG-456`; `Cephalon.Behaviors` startup and execution-slot reflection was classified through `ENG-436`, narrowed by `ENG-457`, and the generated carrier-method subset was retired by `ENG-465`; `Cephalon.Behaviors.Patterns` durable open-generic fallback was narrowed by `ENG-458` and retired by `ENG-467`, and its remaining saga choreography runtime-catalog shape reflection was retired by `ENG-468` through source-generated or explicitly registered `SagaChoreographyRuntimeSlot` metadata; `Cephalon.Behaviors.Http` route/projection/module-builder reflection was classified through `ENG-437` and retired by `ENG-463`, its bounded `ResultModel<>` envelope metadata and generated-profile carrier-method lookups were retired by `ENG-464`, and its generated-profile assembly-scan fallback was retired by `ENG-466` while attribute/profile binding, input-shape, and manual-route reflection remain below; `Cephalon.ReferenceDocs` reflection was classified through `ENG-438` as a by-design permanent `not-claimed` package surface and made machine-checkable through `ENG-439`. After this slice every item in the original `ENG-433` not-yet-classified callout remains closed.
- **Out of scope.** Test, benchmark, sample, and tooling projects. Concrete provider packs only appear when their `Cephalon.*` runtime surface itself contains a hazard pattern (transitive provider-SDK hazards belong in the harness's `knownTransitiveHazards` list, not here).

## Severity classification

| Severity | Meaning | Required remediation before a `claimed` deployment-mode posture |
| --- | --- | --- |
| `excluded-by-design` | Roslyn analyzer / source-generator project that runs in the compiler, never in published output. Properties already declare `IsTrimmable=false`, `IsAotCompatible=false`, `PublishTrimmed=false`, `PublishAot=false`, `PublishSingleFile=false`. | None — the project is intentionally outside the deployment-mode story. |
| `clean-baseline` | Runtime package with no observed reflection / dynamic-code patterns in its `Cephalon.*` source. | Confirm transitive dependencies are clean against the harness's analyzer phase before adopting any `claimed` mode. |
| `low` | Reflection is bounded to closed-generic instantiation over a small known set of types and is reachable only through engine-internal seams. Likely fixable with `[DynamicallyAccessedMembers]` annotations or a small generic-shape rewrite. | Annotate or rewrite, then re-validate. |
| `medium` | Reflection over types loaded from data (e.g. `Type.GetType(persistedString)`). The provider can lift this to AOT-safe by registering a serializer table or polymorphic JSON converter, but the change is non-trivial and the manifest must declare the provider as `claim-overstated` until done. | Replace with a compile-time type registry or polymorphic `System.Text.Json` `[JsonPolymorphic]` baseline. |
| `high` | Reflection that depends on assembly scanning, runtime-loaded plugins, or open-generic adapter instantiation. Cannot become AOT-safe without a structural rewrite (typically a source generator or compile-time discovery contract). | Replace with a source generator + compile-time descriptor, or document a permanent `not-claimed` posture for that package. |

A package is only as portable as its highest hazard. A provider that still resolves persisted app data through `Type.GetType` remains `medium` even when the rest of its surface is clean.

### `high` — non-public reflective access on a third-party transport type in `Cephalon.Data.MySql` (added via `ENG-434`)

This puts `Cephalon.Data.MySql` in the same `high` tier as the assembly-scanning and open-generic adapter blockers — a structural rewrite is required, annotation alone is not sufficient. `ENG-459` retired the separate hosted-service duck-typed capture failure metadata fallback, so the remaining MySQL hazard is now the transport adapter path only.

### `high` — by-design type-introspection in `Cephalon.ReferenceDocs` (added via `ENG-438`)

`Cephalon.ReferenceDocs` is the published documentation generator (an `OutputType=Exe` package shipped through the same release-validation flow as the other `Cephalon.*` runtime packages, listed alongside them in `scripts/validate-signed-package-governance.ps1`). Its job is to enumerate the public API surface of arbitrary other `Cephalon.*` runtime packages — that is what produces `docs/reference/*.md`. The reflection in `Generation/ReferenceDocsGenerator.cs` therefore enumerates constructors, fields, properties, and methods on **types loaded from external assembly references**, by design.

Because the input types are not known at compile time and are not bounded to any closed set (the generator is supposed to document any public type from any reference Cephalon package), there is no source-generator or compile-time descriptor that retires this reflection — the by-design contract of the package is exactly the reflection it performs. Per the [severity classification](#severity-classification), the `high` tier offers two remediation paths: "Replace with a source generator + compile-time descriptor, or document a permanent `not-claimed` posture for that package." The first path is incompatible with the package's purpose; the second path is the durable answer for `Cephalon.ReferenceDocs`. The package therefore stays `not-claimed` for trim / Native AOT / single-file *as a deliberate engineering decision*, not as an unresolved hazard. The matching csproj posture properties (`IsTrimmable=false; IsAotCompatible=false; PublishTrimmed=false; PublishAot=false; PublishSingleFile=false`) were declared in `src/Cephalon.ReferenceDocs/Cephalon.ReferenceDocs.csproj` via `ENG-439` and seeded into the matching `requiredProjectProperties` array in `scripts/deployment-mode-support.json`'s `Cephalon.ReferenceDocs` package entry, so the harness's project-property audit phase can confirm the permanent posture in machine-checkable form.

### Retired — open-generic command/query dispatch in `Cephalon.Data` (added via `ENG-433`, retired via `ENG-462`)

`Cephalon.Data` used to resolve command/query handlers reflectively over runtime command/query types via `MakeGenericMethod`. `ENG-462` replaces that with registered closed-generic dispatch descriptors (`AddCephalonDataCommand<TCommand>()`, `AddCephalonDataCommand<TCommand, TResult>()`, and `AddCephalonDataQuery<TQuery, TResult>()`) consumed by the default `IReadStore` / `IWriteStore` implementations. The two store files no longer reference `System.Reflection`, `MakeGenericMethod`, `CreateDelegate`, or `GetMethod(...)`, and the package row is removed from `scripts/deployment-mode-support.json`. The package returns to clean-baseline absence from the active hazard table, but it still does not claim trim / Native AOT / single-file support until scoped package claims and validation are intentionally promoted.

### Retired — duck-typed exception failure-kind/metadata fallback in CDC capture services (added via `ENG-434`, retired via `ENG-459` / `ENG-460`)

The CDC capture hosted services in `Cephalon.Data.MySql`, `Cephalon.Data.Postgres`, and `Cephalon.Data.Oracle` used to resolve capture-failure metadata through a typed-first / reflection-fallback path. `ENG-459` moved MySQL to a provider-local typed failure-metadata contract, and `ENG-460` applied the same shape to Postgres and Oracle. The hosted-service paths no longer fall back to `exception.GetType().GetProperty("FailureKind" / "Metadata", BindingFlags...)`, so this former medium-tier CDC subsection is now historical context rather than an active hazard list.

### Retired — EventSourcing persisted type-name reflection (added via `ENG-426`, retired via `ENG-461`)

The `Cephalon.EventSourcing.*` provider family used to persist event payloads alongside CLR type names and rehydrate them through `Type.GetType(...)` at read time. `ENG-461` replaces that provider-local reflection with the shared Cephalon event-type registry:

- appends persist the stable registry name returned by `IEventTypeRegistry.GetName(...)`
- reads deserialize through `IEventTypeRegistry.Deserialize(...)` instead of provider-local `Type.GetType(...)`
- descriptors include `FullName` and historical `AssemblyQualifiedName` aliases by default so older rows can still be read after hosts register the concrete event type
- source-generated JSON metadata can flow through `AddCephalonEventTypeWithJsonTypeInfo(...)` for future trim / Native AOT hardening without widening the current global claim

The ten former medium rows for Cassandra, ClickHouse, Elasticsearch, Entity Framework, MongoDB, NATS, Neo4j, OpenSearch, Qdrant, and Redis are therefore removed from `scripts/deployment-mode-support.json`. The EventSourcing family returns to clean-baseline absence from the active hazard table, but it still does not claim trim / Native AOT / single-file support until scoped package claims and validation are intentionally promoted.

### Retired — behavior-owned REST route/projection/module ownership open-generic dispatch (added via `ENG-432` / `ENG-437`, retired via `ENG-463`)

`ENG-463` retires the dominant `Cephalon.Behaviors.Http` REST dispatch hazards without changing the public REST authoring shape:

- `BehaviorRestEndpointGroup` no longer resolves private `MapBehavior{Verb}Core` helpers through `MethodInfo`, no longer calls `MakeGenericMethod(...)`, and no longer invokes the closed helper through `MethodInfo.Invoke`
- `RestBehaviorEndpointProjection` now applies projections through the type-based `BehaviorRestEndpointGroup.MapBehavior(Type, ...)` contract instead of reflecting a generic map-delegate factory
- `RestBehaviorModuleBuilder` now registers ownership through `IBehaviorModuleBuilder.Add(Type, ...)`, so generated-profile ownership no longer selects and invokes `Add<TBehavior>` through reflection
- `IBehaviorModuleBuilder` remains host-agnostic; the new `Type` overloads are ownership declarations only, while REST route publication stays in `Cephalon.Behaviors.Http`

`ENG-464` then retires the two follow-up rows named above: generated REST profile hints now register through `BehaviorRestGeneratedProfileRegistry` from a source-generated module initializer instead of `ContainsBehaviorsAttribute.RegistrationType` method lookup, and optional REST result-envelope OpenAPI projection now uses endpoint metadata through `ResultModelEnvelopeResponseMetadata` instead of constructing `ResultModel<T>` with `MakeGenericType(...)` at runtime. `ENG-466` narrows the generated-profile lane again by making `MapGeneratedProfiles(...)` require registry hints and fail fast when the owning module assembly does not expose them, so it no longer scans the assembly for attributed behavior/profile types.

The package remains `medium`, not clean-baseline, because attribute/profile binding fallback, input-shape inspection, and manual/type-based route-contract reflection still exist.

### Retired — durable-execution open-generic adapter fallback in `Cephalon.Behaviors.Patterns` (narrowed via `ENG-458`, removed via `ENG-467`)

`ENG-458` first moved the source-generated durable path onto closed `DurableExecutionSlot.For<TBehavior, TInput, TState, TOutput>()` registrations, but the package still kept `DurableExecutionSlot.ForType(...)` as a runtime fallback. `ENG-467` removes that fallback entirely:

- `DurableExecutionSlot` no longer references `System.Reflection`, `BindingFlags`, `GetInterfaces()`, `GetMethod(...)`, `MakeGenericMethod(...)`, or `MethodInfo.Invoke`.
- `DurableExecutionStrategy` no longer caches reflection-created slots; it requires a source-generated or explicitly registered `DurableExecutionSlot` and fails fast before event-store work when the slot is missing.
- `DurableExecutionRuntimeCatalogSnapshot` no longer infers the durable input/state/output contract from `IDurableExecution<TInput, TState, TOutput>` at runtime; it projects metadata from the registered slot and fails fast when the slot is missing.

This removes the active high-tier durable open-generic row. `ENG-468` then removes the remaining saga choreography runtime-catalog row, so `Cephalon.Behaviors.Patterns` returns to clean-baseline absence from the active package table while global trim / Native AOT / single-file support remains `not-claimed`.

### Retired — saga choreography runtime-catalog shape reflection in `Cephalon.Behaviors.Patterns` (removed via `ENG-468`)

`ENG-468` moves saga choreography catalog shape into `SagaChoreographyRuntimeSlot` metadata:

- `Cephalon.Behaviors.SourceGen` emits closed `SagaChoreographyRuntimeSlot.For<TBehavior, TInput, TResult>(...)` registrations when a behavior declares `saga-choreography` topology and references the pattern runtime slot.
- manually wired hosts can register the same slot shape explicitly when `AutoRegister=false` or when a custom result contract needs explicit metadata.
- `SagaChoreographyRuntimeCatalogSnapshot` no longer derives behavior/input/result/reactor/publication shape from runtime `GetInterfaces()`, `GetGenericTypeDefinition()`, `GetGenericArguments()`, or `IsAssignableFrom(...)`; missing slots fail fast with source-generator / explicit-registration guidance.

This removes the active medium-tier `Cephalon.Behaviors.Patterns` row from `scripts/deployment-mode-support.json`.

## Clean-baseline (no observed hazards)

The remaining shipped `Cephalon.*` runtime packages — including (but not limited to) `Cephalon.Abstractions`, `Cephalon.Diagnostics`, `Cephalon.Resilience`, `Cephalon.AspNetCore`, `Cephalon.Worker`, `Cephalon.Eventing`, `Cephalon.Eventing.Wolverine`, `Cephalon.Agentics`, `Cephalon.Retrieval`, `Cephalon.Audit`, `Cephalon.Audit.EntityFramework`, `Cephalon.Identity`, `Cephalon.MultiTenancy`, the `Cephalon.MultiTenancy.Governance.*` companion family, the relational / non-relational `Cephalon.Data.*` provider family (the core `Cephalon.Data` package returned to this clean-baseline absence via `ENG-462`; `Cephalon.Data.MySql` is now `high`; `Cephalon.Data.Postgres` and `Cephalon.Data.Oracle` returned to clean-baseline absence from this active table via `ENG-460`; the remaining per-provider packs stay clean-baseline at the source-code layer), the `Cephalon.Edge.*` family, the `Cephalon.Observability.*` family, `Cephalon.Cli`, and `Cephalon.Scaffolding` — show **no `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, `MakeGenericMethod`, `MethodInfo.Invoke`, `BindingFlags`-style member lookup, or `Assembly.LoadFrom` use in their first-party source as of May 6, 2026**. `Cephalon.Abstractions` returned to this clean-baseline set via `ENG-456` after its REST wire-name helpers stopped using enum-field reflection.

This is a strong claim only at the *Cephalon source-code* layer. Every package in this tier still depends on transitive packages whose AOT posture must be validated through the harness's analyzer phase; provider SDKs (`AWSSDK.*`, `Azure.*`, `Google.*`, `Confluent.Kafka`, `Cassandra`, `Neo4j.Driver`, `MongoDB.Driver`, `Elastic.Clients.*`, `Microsoft.EntityFrameworkCore`, `Wolverine`, `Polly`) routinely emit `IL2026` / `IL3050` warnings. ## Refresh discipline

This inventory is refreshed in the same slice that:

- introduces a new `Activator.CreateInstance`, `Type.GetType(string)`, `MakeGenericType`, or `Assembly.LoadFrom` call site in any `src/Cephalon.*` package, **or**
- removes / annotates one of the call sites listed above, **or**
- changes the project-property declarations in any `Cephalon.Analyzers` / `Cephalon.Behaviors.SourceGen` style excluded-by-design package, **or**
- adds, removes, or changes a package-scoped `supportedModes` claim or its required project properties, **or**
- ships a structural remediation (source-generator, compile-time registry) that retires one of the entries here.

A no-change month (no slice touched any of those surfaces) does not require an update; the doc records the state-as-of date in its first-paragraph review window.
